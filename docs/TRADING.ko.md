# 트레이딩 데스크 — TradingAgents × 바이낸스 선물

Munder Difflin 안에서 [TradingAgents](https://github.com/TauricResearch/TradingAgents)의 멀티 에이전트
트레이딩 알고리즘을 **바이낸스 USDⓈ-M 무기한 선물(BTCUSDT, ETHUSDT)** 에 적용한 기능입니다.
모든 에이전트 보고서와 화면은 한국어로 나옵니다.

> **연구용 도구이며 투자 조언이 아닙니다.** LLM 에이전트와 규칙 기반 스캘퍼는 틀릴 수 있고,
> 레버리지 선물은 예상보다 큰 손실이 날 수 있습니다. 반드시 **모의투자 → 바이낸스 데모 → 소액 실거래**
> 순서로 검증하세요.

> **처음 설치하는 방법과 바이낸스 API 자동매매 설정은 [`TRADING-SETUP.ko.md`](./TRADING-SETUP.ko.md)** 에 단계별로 있습니다.
>
> 같은 기능을 **Munder Difflin 없이 독립 실행 앱**으로도 쓸 수 있습니다: [`standalone/README.ko.md`](../standalone/README.ko.md).

## 여는 법

1. 설정 → 일반 → 언어에서 **한국어**를 고릅니다 (앱은 기본 영어로 시작합니다).
2. 오케스트레이터(Michael) 카드를 선택해 **커맨드 센터**를 엽니다.
3. 탭 줄 끝의 **트레이딩** 탭을 누릅니다.

트레이딩 탭은 `개요 · 에이전트 · 에이전트 폴더 · 백테스트 · 거래내역 · 로그 · 설정` 일곱 화면으로 되어 있습니다.

## 두 가지 모드

### 1. 에이전트 알고리즘 모드 (TradingAgents)

TradingAgents의 그래프를 그대로 따릅니다. 종목마다 설정한 간격(기본 60분)으로 실행됩니다.

```
분석가 팀 (병렬)                     리서치 팀                    트레이더
 ├ 기술적 분석가     ┐               강세 연구원 ⇄ 약세 연구원       │
 ├ 파생상품 분석가   ├──────────▶   (N 라운드)      ─▶ 리서치 매니저 ─▶ 트레이더
 ├ 뉴스 분석가       │                                              │
 └ 심리 분석가       ┘                                              ▼
                                리스크 관리 팀: 공격적 → 보수적 → 중립 (N 라운드)
                                              │
                                              ▼
                        포트폴리오 매니저 (최종 등급 + 주문용 JSON)
                                              │
                                              ▼
                     리스크 엔진(코드) ─▶ 주문 실행 (모의 / 데모 / 실거래)
```

| 역할 | 보는 데이터 |
|---|---|
| 기술적 분석가 | 15분·1시간·4시간·일봉의 EMA/SMA, MACD, RSI, 볼린저(밴드폭 백분위), ATR, VWMA, 스윙 지지/저항, 최근 캔들 |
| 파생상품 분석가 | 펀딩비(현재·평균·연환산), 미결제약정 4h/24h 변화, 전체·상위 트레이더 롱숏 비율, 테이커 매수/매도 비율, 베이시스, 호가 불균형 |
| 뉴스 분석가 | CoinDesk·Cointelegraph·Decrypt·Bitcoin Magazine RSS (최근 48시간, 코인 관련 / 거시 분리) |
| 심리 분석가 | 공포·탐욕 지수(alternative.me), 군중 포지셔닝, 헤드라인 논조 |

- TradingAgents의 **펀더멘털 분석가**는 무기한 선물에 맞게 **파생상품 분석가**로 바꿨습니다.
- 에이전트는 도구를 호출하지 않습니다. 모든 수치는 앱이 바이낸스에서 직접 계산해 "검증된 시세 스냅샷"으로 넘깁니다.
  그래서 API 키 없이 **Claude 구독(숨은 세션)** 으로도 돌릴 수 있습니다.
- 등급 척도는 TradingAgents와 같습니다: `Buy / Overweight / Hold / Underweight / Sell`
  (선물에서는 Buy=강한 롱, Overweight=작은 롱, Hold=관망, Underweight=작은 숏, Sell=강한 숏).
- 포트폴리오 매니저는 마지막에 `action, entryType, entryPrice, stopLoss, takeProfit, leverage, riskPct, confidence` JSON을 붙이고,
  리스크 엔진이 이를 검증합니다. JSON이 없으면 한 번 더 요청하고, 그래도 없으면 등급만 보고 **주문 없이** 처리합니다.
- 종료된 거래는 회고(reflection)로 교훈을 남기고, 다음 결정 때 포트폴리오 매니저가 읽습니다.
- 실행이 끝나면 전체 보고서가 마크다운 파일로 저장됩니다 (`에이전트` 화면 → 보고서 폴더 열기).
- 데스크가 **정지** 상태에서 "지금 분석"을 누르면 **분석만** 하고 주문은 내지 않습니다.
- 팀마다 에이전트를 여러 명 둘 수 있습니다. 아래 [에이전트 팀 구성](#에이전트-팀-구성-여러-명의-에이전트)을 보세요.

### 2. 스캘핑 모드

LLM 응답은 수 초~수십 초가 걸려 1분봉 진입 판단에 쓸 수 없으므로, 틱 판단은 규칙 기반으로 하고
에이전트는 **방향 필터**만 맡습니다.

- 매 `확인 주기`(기본 5초)마다 진입 시간대(기본 1분봉)와 추세 시간대(기본 5분봉), 그리고 **실시간 호가·체결 흐름**을 읽어
  롱/숏 점수(0~100)를 계산합니다.
  - 상위 추세 정렬 25 · EMA9/21 모멘텀 20 · 눌림목 회복 또는 스퀴즈 돌파 20 · RSI(7) 10(과열 감점) ·
    **체결 흐름 + 호가 15** · 거래량 동반 10
  - 체결 흐름 15점의 내역은 [아래](#실시간-호가체결-흐름-오더플로우)에 있습니다.
- **레버리지 기본값은 75배**입니다 (설정 → 스캘핑 레버리지, 최대 125배). 실제 레버리지는 바이낸스 레버리지 구간과
  "청산가가 손절가보다 멀리" 규칙에 따라 자동으로 낮아질 수 있습니다 ([75배 거래 카드](#75배-거래-카드-진입손절목표가손익비) 참고).
- 한쪽 점수가 `최소 진입 점수`(기본 65) 이상이고 반대쪽보다 10점 이상 높을 때만 진입합니다.
- ATR·스프레드 필터, 청산 후 쿨다운, 시간당 최대 진입 수를 지킵니다.
- 손절 = 진입가 ∓ 1.2×ATR, 익절 = 진입가 ± 1.8×ATR (설정 가능). +1R에 도달하면 손절을 본전(+수수료)으로 옮기고,
  `최대 보유 시간`이 지나거나 강한 반대 신호가 나오면 청산합니다.
- **방향 필터 데스크**: 15분마다 TradingAgents의 분석가·강세/약세 연구원·리스크 관점을 한 번의 호출로 압축해
  `롱만 / 숏만 / 양방향 / 진입 금지`를 정합니다. 필터가 30분 이상 갱신되지 않으면 양방향으로 돌아갑니다.
- **경험 필터**: 백테스트에서 손해 본 셋업이면 진입하지 않습니다 ([백테스트](#백테스트-과거-차트-리테스트) 참고).

### 75배 거래 카드 (진입·손절·목표가·손익비)

스캘핑 모드의 **개요** 화면에는 종목마다 지금 진입한다면의 거래 카드가 계속 갱신됩니다.

| 항목 | 내용 |
|---|---|
| 진입가 · 손절가 · 목표가 | 지금 가격, 진입가 ∓ 1.2×ATR, 진입가 ± 1.8×ATR (각각 %도 표시) |
| 손익비 | 가격 기준 손익비와 **수수료·슬리피지를 뺀 실질 손익비** |
| 레버리지 | 요청(75배) → 실제 적용 레버리지 (거래소 구간·청산 안전 규칙으로 낮아지면 이유 표시) |
| 청산가 | 격리 마진 기준 예상 강제 청산가와 진입가 대비 거리 |
| 수량 · 명목가 · 증거금 | 리스크 엔진이 정한 크기 |
| 손절 시 / 목표 시 | 손익(USDT)과 **증거금 대비 수익률(ROE)** |
| 수수료 · 본전 | 왕복 수수료와 본전이 되려면 필요한 가격 변동 % |

청산가는 바이낸스 공식 격리 청산 공식 `LP = (WB + cum − side·Q·EP) / (Q·MMR − side·Q)`로 계산합니다.
유지 증거금률(MMR)과 구간 보정값(cum)은 계정 연결 시 `GET /fapi/v1/leverageBracket`에서 읽고, 모의투자에서는
내장 추정 구간을 씁니다 (카드에 "추정" 표시).

**75배에서 꼭 알아야 할 것 — 수수료가 손익비를 지배합니다.** 1분봉 ATR이 0.12% 안팎일 때 기본 설정의 손절폭은 약 0.15%,
목표폭은 약 0.22%입니다. 테이커 수수료(0.05%×2)와 슬리피지(2bp×2)를 빼면 **실질 손익비가 0.3:1 안팎**까지 떨어지고,
75배에서 손절 한 번은 증거금의 약 −22%입니다. 실질 손익비가 1 아래면 카드에 경고가 뜹니다. 손절·목표 ATR 배수를 넓히거나
진입 시간대를 3분·5분봉으로 올리고, 반드시 백테스트로 확인하세요.

### 실시간 호가·체결 흐름 (오더플로우)

스캘핑 모드에서는 바이낸스 웹소켓을 직접 엽니다 (설정 → "실시간 호가·체결 흐름 읽기", 기본 켜짐).

- 체결: `wss://fstream.binance.com/market/stream?streams=<종목>@aggTrade`
- 호가 20단계(100ms): `wss://fstream.binance.com/public/stream?streams=<종목>@depth20@100ms`
- 끊기면 1초부터 최대 60초까지 늘려 가며 다시 연결하고, 바이낸스의 24시간 연결 제한 전에 스스로 다시 엽니다.
  웹소켓이 15초 이상 조용하면 REST 체결 내역으로 대신 계산합니다.

| 계산 | 쓰임 (15점) |
|---|---|
| 1분 체결 우위(매수 비율)와 1분 CVD | 같은 방향이면 6점 |
| 5분 CVD | 같은 방향이면 3점 |
| 대량 체결 (기본 10만 USDT 이상) | 내 방향이 2건 이상 많으면 3점 |
| 흡수 (한쪽 공세에도 가격이 안 밀림) | 반대쪽 공세가 흡수되면 +3점 |
| 호가 불균형 (매수잔량 ÷ 매도잔량) | 내 방향 우위면 3점 |
| 호가벽 (보이는 호가 중앙값의 4배 이상) | **목표가 앞에 벽이 있으면 −6점** |

개요 화면의 **호가·체결 흐름** 카드에 CVD, 체결 속도, 대량 체결, 불균형, 벽, 스프레드가 실시간으로 나옵니다.

## 백테스트 (과거 차트 리테스트)

**백테스트** 화면에서 지난 바이낸스 차트를 데스크로 다시 돌려 봅니다. 진입마다 손절·익절·청산까지 끝까지 따라가고,
결과를 경험으로 쌓습니다. 백테스트는 주문을 내지 않습니다.

### 과거 데이터

바이낸스 공식 데이터 아카이브(`data.binance.vision`, USDⓈ-M 일별 파일)를 내려받아 `trading/history/`에 저장합니다.

| 파일 | 쓰임 |
|---|---|
| `klines/1m` | 1분봉 (아카이브에 아직 없는 최근 날은 REST로) |
| `aggTrades` | **모든 체결 (테이프)** — 초 단위로 줄여 체결 흐름을 재현 (하루 약 10~30MB, 한 번에 최대 7일) |
| `bookDepth` | 중간가 ±1% 호가 깊이 (약 30초 간격) — 호가 불균형 |

호가 최우선 단계(bookTicker) 아카이브는 바이낸스가 더 이상 내지 않아, 과거 재현의 호가 쪽은 ±1% 깊이입니다.
호가벽은 실시간에서만 봅니다. 파일은 보통 하루 늦게 올라옵니다.

### 1. 스캘핑 · 내장 리플레이

실전 스캘퍼 코드(`evaluateScalp`·`manageScalp`·리스크 엔진)를 그대로 과거에 돌립니다.

- 체결 테이프가 있는 날은 **초 단위**(기본 5초마다 판단), 없는 날은 1분 단위로 진행합니다.
- 그 순간까지 닫힌 캔들과 그 순간의 체결 흐름만 봅니다 (미래 데이터 차단 — 테스트로 검증).
- 진입은 그때 가격 + 슬리피지 + 테이커 수수료, 손절·익절·강제 청산은 **초마다** 확인합니다 (1분봉이면 한 봉이 둘 다 닿을 때 손절 먼저).
- 쿨다운, 시간당 진입 수, 일일 손실 한도, 연속 손실, 본전 손절, 시간 청산, 강한 반대 신호 청산이 실전과 같습니다.
- 펀딩비는 반영하지 않습니다 (스캘핑은 보유 시간이 짧음).

### 2. 스캘핑 · 노틸러스 엔진 (NautilusTrader)

판단은 데스크가, 체결은 [NautilusTrader](https://nautilustrader.io)의 모의 거래소가 합니다.

1. 내장 리플레이가 같은 기간의 판단(신호)을 모두 내보냅니다.
2. NautilusTrader가 그 기간의 **바이낸스 체결 전부(aggTrades)** 를 하루씩 TradeTick으로 읽고 (스트리밍, 최대 7일), 데스크의 브래킷 주문
   (시장가 진입 · STOP_MARKET 손절 · MARKET_IF_TOUCHED 익절)을 실제 체결 흐름에 맞춰 체결합니다
   (L1, 체결 기반 매칭, 지연 50ms, 1틱 슬리피지 확률 50%, 테이커/메이커 수수료, 레버리지 마진 계정).
3. 결과 화면에 노틸러스 결과와 같은 신호의 내장 리플레이 결과가 함께 나옵니다.

노틸러스는 앱에 들어 있지 않습니다. 처음 한 번 **Python 3.12~3.14**가 필요하고, 백테스트 화면의 **노틸러스 설치**를 누르면
앱 데이터 폴더 안에 전용 가상환경(`trading/nautilus/venv`)을 만들고 `nautilus_trader==1.231.0`을 설치합니다
(수백 MB, 몇 분). 시스템 Python은 건드리지 않습니다. 노틸러스 백테스트에는 강제 청산과 펀딩비가 반영되지 않습니다
(데스크가 손절이 항상 청산가보다 먼저 닿도록 레버리지를 정합니다).

### 3. 에이전트 팀 리플레이 훈련

에이전트 알고리즘 모드의 **팀 전체**가 과거 시점에서 판단하고, 그 뒤의 실제 1분봉으로 채점합니다.

- 기간 안에서 고르게 고른 시점(기본 4개)마다 파이프라인을 한 번씩 돌립니다 (시점마다 실시간 분석과 같은 LLM 호출 수).
- 그 시점 이전에 닫힌 캔들·펀딩비·포지셔닝(바이낸스가 최근 30일만 제공)·공포탐욕지수만 줍니다. 과거 뉴스 기록이 없어 뉴스 분석가는 빠집니다.
- **기억 차단**: 날짜를 주 단위로 2031년으로 옮기고 모든 가격에 한 비율(0.55~0.85 또는 1.25~1.7)을 곱해서 보여 줍니다.
  모델이 "그때 무슨 일이 있었는지" 기억으로 맞히지 못하게 하려는 것입니다. 답의 가격은 다시 실제 가격으로 되돌린 뒤 거래를 따라갑니다.
- 에이전트는 그 시점 **이전의** 자기 판단 기록만 보고, 데스크 교훈은 보지 않습니다 (미래 정보 차단).
- 결정한 거래는 1분 뒤 시장가 진입으로 손절·익절·최대 보유 시간까지 따라갑니다.
- 리플레이 세션은 각 에이전트 폴더의 `.sessions/replay-<종목>`에서 따로 돕니다.

### 경험 쌓기

"경험으로 쌓기"를 켜면 (기본 켜짐):

- **스캘핑**: 거래마다 진입 당시 조건(방향 · 추세 순/역방향 · 점수대 · 변동성대 · 체결 흐름 동조/역행)으로 묶어 저장합니다
  (`trading/experience/scalp-<종목>.json`). 실전에서 같은 셋업이 나오면 그 기록을 보고, **20건 이상인데 평균 R이 마이너스면
  진입하지 않습니다** (개요에 "백테스트 경험 — … → 진입 안 함"). 셋업 기록이 적으면 더 넓은 묶음(방향 · 변동성대)이
  2배 표본(40건)으로 판단합니다. 같은 기간을 다시 테스트하면 이전 기록을 대체해 중복으로 세지 않습니다.
  설정 → 스캘핑의 "경험 필터"와 "필요한 리플레이 거래 수"로 조정하고, 백테스트 화면에서 셋업별 기록을 보고 지울 수 있습니다.
- **에이전트**: 방향 판단마다 4시간 뒤 가격으로 채점해 각자의 `record.json`·성적표에 "(리플레이)"로 남기고,
  거래 결과는 각 에이전트의 `lessons.md`와 데스크 교훈에 `[과거 리플레이]`로 들어가 실전 판단 때 다시 읽힙니다.

결과를 지우면 그 결과로 쌓인 스캘퍼 경험도 함께 빠집니다.

## 에이전트 팀 구성 (여러 명의 에이전트)

설정 → **에이전트 팀 구성**에서 팀마다 인원을 정합니다. 자리마다 전문 관점(페르소나)이 다르고,
이들의 의견을 종합해 그 팀의 결과 하나를 냅니다. 인원을 모두 1로 두면 원본 TradingAgents와 같습니다.

| 팀 | 인원 | 자리별 전문 관점 (자리 순서대로) | 종합 방법 |
|---|---|---|---|
| 분석가 (역할마다) | 1~3 | 기술: 추세추종 · 오실레이터/평균회귀 · 가격구조/변동성<br>파생: 펀딩/베이시스 · 포지셔닝/청산 · 오더플로우<br>뉴스: 크립토 기자 · 거시 이코노미스트 · 규제/이벤트<br>심리: 역발상 · 모멘텀 심리 · 군중 포지셔닝 | 팀원들이 병렬로 보고서를 쓰고 끝에 `Stance`(강세/약세/중립)와 확신도를 붙임 → **팀장**이 팀원 보고서 전부와 코드 집계 투표를 읽고 하나의 팀 보고서로 종합 |
| 리서치 (진영마다) | 1~3 | 강세: 모멘텀 · 수급/포지셔닝 · 촉매/거시<br>약세: 추세 약화 · 레버리지/청산 · 이벤트/거시 | 강세 1 → 약세 1 → 강세 2 → 약세 2 … 순서로 토론. 모두 전체 기록을 봄 → 리서치 매니저가 판정 |
| 트레이딩 | 1~5 | 스윙 · 돌파 · 되돌림 · 퀀트 · 파생 흐름 | 트레이더들이 서로 보지 않고 제안 (`FINAL TRANSACTION PROPOSAL`) → **헤드 트레이더**가 제안 전부와 투표 집계를 읽고 하나의 실행 계획으로 종합 |
| 리스크 관리 (성향마다) | 1~2 | 공격: 기회 포착 · 추세 추격<br>보수: 자본 보존 · 꼬리 위험<br>중립: 균형 조정 · 시나리오 분석 | 공격 1 → 보수 1 → 중립 1 → 공격 2 … 순서로 토론 |
| 포트폴리오 위원회 | 1~5 | CIO · 리스크 책임자 · 퀀트 PM · 매크로 PM · 실행 PM | 위원들이 서로 보지 않고 각자 등급 + 주문 JSON을 냄 → **코드가 투표 집계** (아래) |
| 방향 필터 패널 (스캘핑) | 1~5 | 추세 · 흐름 · 리스크 · 심리 · 구조 판정관 | 판정관들이 각자 방향을 냄 → **코드가 방향별 찬성 투표로 집계** (아래) |

프리셋: **역할당 1명**(원본) · **표준 위원회**(기본: 분석가 2 · 연구원 2 · 트레이더 3 · 리스크 1 · 위원회 3 · 패널 3) ·
**확장 위원회**(3 · 3 · 5 · 2 · 5 · 5).

### 주문에 쓰이는 결정은 코드가 집계합니다

모델이 다른 모델의 투표를 읽고 해석하는 단계를 주문 경로에 두지 않았습니다. 포트폴리오 위원회와 방향 필터 패널은
독립 투표를 코드가 합의 규칙으로 집계합니다.

**합의 규칙** (설정에서 선택, 응답한 위원 기준):

| 규칙 | 기준 |
|---|---|
| 과반 (기본) | 응답 위원의 절반 초과 |
| 3분의 2 이상 | 응답 위원의 2/3 이상 |
| 만장일치 | 응답 위원 전원 |

정족수: 자리의 과반이 응답해야 합니다. 못 미치면 위원회는 그 실행을 실패로 처리(주문 없음)하고, 패널은 이전 방향을 유지합니다.

**포트폴리오 위원회**

1. 가장 많은 표를 받은 행동(롱/숏/청산/관망)이 후보. 1위가 동률이면 관망.
2. 후보의 득표율이 합의 규칙을 넘어야 확정. 못 넘으면 관망.
3. 진입이면 찬성 위원들의 값으로 주문을 만듭니다.
   - 손절가·익절가: 찬성 위원들의 **중앙값**
   - 지정가: 찬성 위원 과반이 지정가를 냈을 때만, 그 가격들의 중앙값
   - 레버리지: 중앙값(내림), 확신도: 중앙값
   - **포지션 규모 = 리스크 비율 중앙값(거래당 최대 손실 한도로 먼저 제한) × 찬성 비율** (3명 중 2명 찬성이면 만장일치일 때의 2/3 규모)
4. 그 뒤 리스크 엔진이 평소처럼 검증합니다 (손절 방향, 손익비, 최소 확신도, 레버리지 상한 등).

**방향 필터 패널**: 롱만·양방향 표는 롱 허용, 숏만·양방향 표는 숏 허용으로 셉니다. 허용 비율이 합의 규칙을 넘는 방향만
열립니다 (둘 다 열리면 양방향, 하나면 그 방향만, 없으면 진입 금지).

예) 판정관 3명이 `롱만, 롱만, 양방향`이면 롱 허용 3/3, 숏 허용 1/3 → **롱만**.

### 실패해도 멈추지 않습니다

- 팀원 한 명이 실패하면 나머지로 진행합니다. 한 명만 남으면 그 보고서를 그대로 씁니다.
- 팀장·헤드 트레이더 호출이 실패하면 팀원 보고서를 이어 붙이거나 다수 의견의 제안을 그대로 씁니다.
- 토론 발언자 한 명이 실패하면 그 차례만 건너뜁니다.

### 호출 수와 속도

설정 화면에 예상 호출 수가 표시됩니다. 토론·리스크 1라운드 기준:

| 구성 | 파이프라인 1회 LLM 호출 |
|---|---|
| 역할당 1명 | 12회 |
| 표준 위원회 | 27회 |
| 확장 위원회 | 40회 |

`동시 실행 에이전트 수`(기본 4)가 데스크 전체에서 동시에 도는 호출 수를 제한합니다.
Claude 구독은 호출마다 숨은 Claude Code 세션을 하나씩 띄우고 요금제 사용량에서 차감되므로, 인원을 늘리면
사용량 한도에 더 빨리 닿습니다. 닿으면 분석 간격을 늘리거나 인원을 줄이세요.

### 화면

- **에이전트** 화면: 팀마다 팀장(굵게) 아래에 팀원이 들여쓰기로 나오고, 각 팀원의 투표(강세/약세/중립, 롱/숏/관망)가 표시됩니다.
- 최종 결정 카드에 위원회 투표, 합의 여부, 규모 비율이 나옵니다.
- 보고서 파일에는 팀원별 보고서, 트레이더별 제안, 위원회 의사록(위원별 등급·행동·확신도·손절·익절 표)이 모두 들어갑니다.

## 에이전트별 프로젝트 폴더

에이전트마다 자기 프로젝트 폴더가 있고, 그 안에서 일합니다. 트레이딩 탭의 **에이전트 폴더** 화면에서 모든 에이전트의
성적을 보고 폴더를 열 수 있습니다 (에이전트 화면에서 에이전트를 고른 뒤 **폴더 열기**도 됩니다).

```
<앱 사용자 데이터>/trading/agents/
├─ CLAUDE.md                    ← 모든 에이전트 공통 지침 ("## 공통 지침" 아래에 쓰기)
├─ technical-trend/             ← 기술적 분석가 · 추세추종 차티스트
│  ├─ CLAUDE.md                 ← 이 에이전트의 정체와 "## 내 지침" (직접 수정)
│  ├─ scorecard.md              ← 성적표 (자동)
│  ├─ record.json               ← 판단 기록과 채점 결과 (자동)
│  ├─ lessons.md                ← 이 에이전트가 투표한 거래의 결과 (자동)
│  ├─ outputs/BTCUSDT/*.md      ← 최근 보고서·발언 (종목마다 최근 30개)
│  └─ .sessions/BTCUSDT/        ← 이 에이전트의 Claude 세션이 실행되는 곳
├─ technical-lead/              ← 기술적 분석 팀장
├─ trader-lead/                 ← 헤드 트레이더
├─ portfolioManager-risk/       ← 포트폴리오 위원회 · 리스크 책임자
└─ …                            ← 현재 팀 구성의 모든 에이전트 (표준 위원회 31명)
```

- **폴더 이름**은 역할과 자리(전문 관점)로 정해집니다. 인원을 줄였다 다시 늘려도 같은 자리는 같은 폴더·지침·기록을 이어 씁니다.
  위원회 집계·리스크 엔진·주문 실행은 코드라서 폴더가 없습니다.
- **지침 고치기**: 에이전트 폴더의 `CLAUDE.md`에서 `## 내 지침` 아래에 쓰면 다음 호출부터 반영됩니다.
  모든 에이전트에 적용하려면 맨 위 `agents/CLAUDE.md`의 `## 공통 지침` 아래에 씁니다.
  - Claude 구독: 세션이 에이전트 폴더 안(`.sessions/<종목>`)에서 실행되므로 Claude Code가 두 `CLAUDE.md`를 직접 읽습니다.
  - API·호환 서버: 데스크가 두 파일의 사용자 작성 부분을 시스템 프롬프트에 넣습니다.
  - 리스크 한도·손절 의무·주문 형식은 코드가 강제하므로 지침으로 바뀌지 않습니다.
- **성적(적중률)**: 방향 판단(강세·롱·롱만 / 약세·숏·숏만)을 시장 가격으로 채점합니다.
  에이전트 알고리즘 판단은 4시간 뒤, 스캘핑 방향 필터 판단은 1시간 뒤의 1분봉 가격과 비교합니다.
  중립·관망·청산과 토론자(강세/약세 연구원, 리스크 토론자)·회고 담당은 채점하지 않습니다.
  "판단 방향 평균"은 판단한 방향으로 가격이 평균 얼마나 움직였는지입니다.
- **기억**: 에이전트는 답하기 전에 자기 기록을 다시 봅니다 — 자기 적중률, 같은 종목의 최근 판단 5개와 그 결과,
  자기가 투표한 거래의 결과 3개. 판단의 근거는 여전히 그때 주어진 자료입니다.
- **거래 결과**: 에이전트 모드 거래가 종료되면, 그 진입을 결정한 실행에서 방향 판단을 낸 에이전트마다
  `lessons.md`에 "거래 방향과 같았는지, 판단이 맞았는지"가 한 줄씩 남습니다.
- **사무실 프로젝트로 등록**: 에이전트 폴더 화면의 버튼을 누르면 `agents` 폴더가 Munder Difflin 프로젝트(방)로 등록됩니다.
  사무실 직원을 이 프로젝트로 고용하면 에이전트들의 지침·성적표를 읽거나 고치게 할 수 있습니다.

## 실행 환경

| 환경 | 주문 | 필요한 것 |
|---|---|---|
| 모의투자 (기본) | 내 컴퓨터에서 시뮬레이션 (수수료·슬리피지·펀딩비·손절/익절·격리 청산 반영) | 없음 |
| 바이낸스 데모 | `demo-fapi.binance.com` 에 실제 주문 | demo.binance.com 에서 만든 데모 API 키 |
| 실거래 | `fapi.binance.com` 에 실제 자금으로 주문 | 실거래 API 키 + 설정의 위험 고지 동의 |

- 시세 분석은 항상 실거래 공개 시세를 씁니다.
- 손절·익절은 바이낸스 **Algo Order API**(`POST /fapi/v1/algoOrder`, `STOP_MARKET` / `TAKE_PROFIT_MARKET`, reduce-only,
  마크가격 기준)로 겁니다. 2025년 12월 이후 `/fapi/v1/order`로는 조건부 주문이 거부(-4120)되기 때문입니다.
- **손절 주문이 실패하면 즉시 포지션을 청산**합니다. 보호 없는 포지션은 두지 않습니다.
- 헤지 모드 계정이면 `positionSide`를 지정해 주문합니다.
- 실거래 API 키는 **선물 거래만 허용, 출금 비활성화, IP 허용 목록** 설정을 권장합니다.
- 키는 운영체제 보안 저장소(Electron safeStorage)로 암호화되어 저장되고 화면에 다시 표시되지 않습니다.

## 자동매매 (설정 → 자동매매)

| 옵션 | 기본값 | 내용 |
|---|---|---|
| 앱을 열면 데스크 자동 시작 | 꺼짐 | 앱 실행 약 8초 뒤 저장된 모드·환경·종목으로 시작 |
| 거래 중 컴퓨터 잠자기 방지 | 켜짐 | 데스크가 도는 동안 Electron powerSaveBlocker로 앱 일시 중단 방지 |
| 데스크톱 알림 | 켜짐 | 진입·청산·일일 한도 중단·오류 (오류는 1분에 한 번까지) |
| 로그인하면 앱 실행 | OS 설정 | 즉시 적용, 자동 시작과 함께 쓰면 재부팅 후 자동 재개 |

실거래를 시작할 때마다 바이낸스 `GET /sapi/v1/account/apiRestrictions`로 키 권한을 읽어,
**출금 권한이 켜져 있거나 선물 권한이 없으면 시작을 거부**합니다. IP 제한이 없으면 경고만 남깁니다.

## 리스크 엔진 (코드가 강제)

LLM이 무엇을 말하든 아래 규칙은 코드에서 강제됩니다.

- 손절가 없는 진입 거부, 손절이 잘못된 방향이면 거부, 현재가가 이미 손절가를 넘었으면 거부
- 포지션 크기 = (자본 × 거래당 최대 손실%) ÷ (손절 거리 + 왕복 수수료 + 슬리피지) — 모델이 말한 수량은 쓰지 않음
- 레버리지 상한(데스크 전체 최대 125배 · 기본 75배, 에이전트 모드는 따로 기본 10배), 바이낸스 **레버리지 구간**(명목가가
  클수록 최대 레버리지가 낮아짐), 그리고 **격리 청산가가 손절 거리의 1.25배 이상 멀도록** 레버리지 자동 하향
- 자본 대비 최대 명목가, 가용 증거금, 거래소 최소 수량/최소 명목가
- 최소 손익비(기본 1.5:1), 최소 확신도(기본 0.55)
- **일일 손실 한도**(기본 -4%)나 **연속 손실**(기본 4회)에 닿으면 그날은 신규 진입 중단 (기존 포지션 관리는 계속).
  하루 기준은 UTC이며, 앱을 다시 켜도 카운터가 유지됩니다.

## 알아둘 점

- 데스크를 **정지해도 열린 포지션은 그대로** 남습니다. 데모/실거래는 거래소에 걸린 손절·익절이 유지되지만,
  모의투자 포지션은 다시 시작할 때까지 손절·익절이 감시되지 않습니다.
- 앱이 꺼져 있으면 아무것도 실행되지 않습니다 (Munder Difflin의 "로그인 시 열기"·"잠자기 방지" 설정을 참고하세요).
- 바이낸스 선물 API는 일부 지역(IP)에서 막혀 있습니다 (HTTP 451).
- 입금·출금이 있으면 일일 손익 계산(자본 변화 기준)이 왜곡될 수 있습니다.
